# Shizuku 能力边界

> 依据：AOSP `packages/Shell/AndroidManifest.xml`（`master` 分支）中 `com.android.shell`
> 声明的 531 个权限。完整清单见文末附录。
>
> 数据获取：`web/raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/packages/Shell/AndroidManifest.xml`

## 一、先说机制：Shizuku 给的是「shell 身份」，不是「超级权限」

Shizuku 做的事只有一件：让你的进程能借用 **shell（uid 2000）** 的 Binder 身份起进程/调服务。

因此"能做什么"= **`adb shell` 能做什么**，取决于两条路径：

| 路径 | 生效方式 | 限制 |
|---|---|---|
| 起 shell 进程执行命令 | `Shizuku.newProcess("sh -c ...")` | 受 SELinux `shell` 域约束 |
| Binder 直调系统服务 | `SystemServiceHelper.getSystemService()` + `ShizukuBinderWrapper` | 需要 hidden AIDL stub，通常拿不到 |

**531 个权限里绝大多数用不上**（TV 调谐器、USB、健康、卫星、车机……）。
与自动化相关的约 70 个，下面按用途分组。

## 十一、有权限但依然做不到（重要，别浪费时间）

| 目标 | 为什么不行 |
|---|---|
| 写 `/dev/uinput`（伪造 HID 设备） | **SELinux 域限制**，不是权限问题。`shell` 域无 `uinput_device` 写权限 |
| 写 `/dev/input/event*`（`sendevent`） | 同上，`input_device` 对 shell 通常只读 |
| 读别的 App 私有 `/data/data/<pkg>` | `shell` 域无权限；非 debuggable 无 `run-as` |
| 截取 `FLAG_SECURE` 内容 | SurfaceFlinger 层直接返回黑帧，权限再大也不行 |
| 改 IMEI / 序列号 | 无 API，需改分区（root） |
| 改 `Build.*` 字段 | 内存只读，需 hook 或 root |
| 绕过证书 pinning | 需要注入目标进程 |
| 改 `ANDROID_ID` | 存在 `/data/system/users/0/settings_ssaid.xml`，shell 无写权限 |

## 十二、接口层：四种调用方式

| 方式 | 形式 | 稳定性 | 建议 |
|---|---|---|---|
| **`cmd <service>`** | `cmd package list packages` | 高（官方子命令） | **首选** |
| `dumpsys <service>` | 只读文本 | 高（格式随版本变） | 解析要容错 |
| 系统二进制 | `input` / `screencap` / `pm` / `am` / `ime` / `wm` | 高 | 首选 |
| `service call <name> <code>` | 裸 Binder 事务 | **低**（code 会变） | 仅兜底 |
| Binder 直调 | `SystemServiceHelper` + hidden AIDL | **极低**（需 stub） | 不推荐 |

常用 `cmd` 子命令：`activity` `package` `window` `input` `settings` `appops` `statusbar`
`notification` `uimode` `overlay` `media_session` `deviceidle` `jobscheduler` `alarm`
`power` `wifi` `connectivity` `display` `accessibility` `usb` `telecom` `role` `users`。

## 十三、怎么在目标机型上核实

清单来自 AOSP，**OEM ROM 会裁切**（国产 ROM 常砍 `ACCESS_SURFACE_FLINGER`、
`READ_PRIVILEGED_PHONE_STATE` 等）。上线前必须在目标机型实测：

```bash
# 1. 实际授予的权限（与 AOSP 清单比对）
adb shell dumpsys package com.android.shell | sed -n '/grantedPermissions/,/^$/p'

# 2. 逐条验证关键能力
adb shell screencap -p /data/local/tmp/a.png && echo "screencap OK"
adb shell input tap 500 500 && echo "inject OK"
adb shell dumpsys window windows | head -5
adb shell pm clear com.example.app
adb shell cmd appops set com.example.app CAMERA allow
adb shell settings put global policy_control immersive.full=*
adb shell settings put global policy_control null*

# 3. SELinux 域确认（判断 uinput 是否可能）
adb shell id
adb shell getenforce
adb shell ls -Z /dev/uinput /dev/input/ 2>&1
```
